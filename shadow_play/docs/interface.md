# 三人共用的映射接口（v0.3）

## 数据的边界

```text
剧本关键帧 -> 插值 -------------------+
触控关节点 -> 火柴人到控制杆转换 -------+-> ShadowPose -> MotionMapper -> AxisOutput[]
人体关键点 -> 置信度/镜像/姿态重定向 ---+                                  |
                                                                     电机后端
```

`MotionMapper` 不区分模式，不识别人，也不读取视频。它消费的是转换完成的控制杆目标。总控程序每次只让选中的模式更新相应杆；剧本可控制全部五杆，当前触控/摄像头模式只控制武松，虎头和虎尾保持中立。老虎互动动作层尚未加入。

## 上游必须提供

五根杆的规范名称：`wusong_neck`、`wusong_left`、`wusong_right`、`tiger_head`、`tiger_tail`。分别连接武松脖子处、左手、右手、老虎头部耳朵处和尾巴处。旧名 `wusong_body` 仍可被解析为颈部主杆，新的资源和输出不再使用它。

每杆 `(x,y,valid)`；坐标 [-1,1]，中立为零，舞台右/上为正。左右手按角色自身命名。没有新数据、置信度不足或不可用的点不应伪造为有效的 `(0,0)`。

映射器使用总控程序本地 `steady_clock` 的接收时间，不直接比较不同电脑/进程的时间戳。网络接收层应按帧号丢弃重复和乱序消息；远端发送时间可记录作诊断，但不能未经时钟同步用来驱动本模块的时间。

只对新帧调用 `submit_pose`，持续调用 `step`；同一时刻可以先提交再更新，但时刻不可倒退。接口本身不是线程安全的，各输入线程应先进入队列，由同一个控制线程调用映射器。

已收到的 FOLLOW 交接包明确：最终结果为 `(9,3)` 的 `[x,y,confidence]` 数组，坐标对应已旋转正向的 1280×720 画面，左上为原点。`integrations/follow/pose_sender.py` 将其转换成归一化 camera v2 帧。视觉没有单独的脖子点，`Retargeter` 用双肩中点近似颈部；双腕相对同侧肩并按肩宽缩放成手杆目标。实际安装左右、参考站位及机械幅度需联调。详见 [输入协议](input_protocol.md) 和 [视觉接入步骤](vision_to_motor.md)。

## 下游交给队员一

一次 `step` 返回一组 `AxisOutput`，顺序与标定 CSV 相同。后端应按 `axis_id` 建立通道对应，使用 `angle_deg`（度）作为控制目标。`limited_target_deg` 和三个限制标志只是诊断数据。

PWM 周期、角度到脉宽的换算、AXI 寄存器地址、驱动设备路径、使能/急停、故障反馈和电机供电由电机后端及真实板卡设计确定，不在映射核心中写死。

当前 `AxisOutput` 是内存中的 C++ 对象，含 `std::string`，**不能直接 memcpy 成网络/串口数据包**。同进程可直接传给后端函数。新增 `JsonlMotorBackend` 提供带版本、输出序号和整组轴目标的序列化，CLI 用 `--motor-format jsonl` 导出；默认 CSV 保留原轨迹工具兼容。该格式没有自带硬件传输和 AXI 接收器，详见 [硬件电机接口](hardware_motor_protocol.md)。

第一次接真实硬件前需队员一确认：

| 项目 | 当前状态 |
| --- | --- |
| 实际轴数及每轴 `axis_id` | 待确认；示例十轴只是模拟 |
| 杆与轴的对应、安装正方向 | 待测量 |
| 每轴零位、安全范围、允许速度 | 待标定 |
| 后端接收角度的接口及成组更新方式 | 待确认 |
| 上电初始化/归位后当前指令的获取方式 | 待确认 |
| 失联/程序崩溃时的硬件或后端保护 | 待确认 |

这套输出是开环的目标指令，不代表电机已到位。真实角度或到位状态只能由后端提供的反馈确定。
