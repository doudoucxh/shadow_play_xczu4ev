# UART引脚对调对照试验

用户在两台驱动器确认UART/115200/地址1/0x6B、原映射版本和状态查询均无回传后，明确要求交换RX/TX试验。原报告中的RX/TX指电机端标识，原实现与该报告一致；对调是独立诊断候选，不覆盖接线来源或自动改为正式配置。

| 机构 | 原FPGA TX / RX | 对调候选TX / RX | 寄存器 |
|---|---|---|---|
| 人物 | F15 / H13 | H13 / F15 | 0xA0040000 |
| 老虎 | H14 / L13 | L13 / H14 | 0xA0050000 |

按原接线描述，对调会使FPGA输出与电机TX相接，已向用户说明并提出串联1kΩ电阻；用户回答没有电阻、仍要求继续。该器件Bank46的LVCMOS33只支持4/8/12/16mA驱动档，第一次2mA离线配置被Vivado拒绝，未生成/加载；候选使用最低合法4mA、SLOW。驱动档位不是硬限流，也不能据此证明对接输出没有风险。

`build_swapped_pins.tcl`只读打开原已验证布线检查点，解开四个I/O缓冲及其八条网络，重新定位后保留其它路由。重新执行时序、DRC、总线偏斜、完整路由和十路舵机引脚检查，并核对其它全部端口未变。原工程、原位流和当前板端镜像保留。验证完成才可打包。

`prepare_swapped_uart_bundle.py`比对原/新I/O报告，确认只有四个UART信号换脚、输出4mA，保留其它端口及全部UART参数。独立release保存完整位流；串口传输使用与原位流做XOR后的压缩差分。`install_uart_swap_data.py`只做SD数据安装，必须匹配原位流摘要、差分尺寸和目标位流摘要，拒绝越界路径、链接、重复成员或超大包；不访问硬件。

`load_swapped_uart_candidate.py`默认离线核验。加载必须绑定当前标准UART镜像、启动ID、停止序号及新一次实际执行器断电确认；停原临时HDMI sink、确认无人持有PL映射后加载易失PL，保留原标记、事故锁和启动文件。显示使用另一独立副本，只替换精确位流摘要，不修改旧服务或增加自启。

查询端必须显式选择`--pin-map swapped`，与加载标记、摘要和端口表完全匹配；限定地址1版本查询，按每启动/镜像/机构的排他使用标记只允许尝试一次。十路PWM均保持关闭，不使能、不移动、不回零、不清位置、不扫描或自动重试。失败同样保留使用标记和原始诊断。此入口不等于正式丝杆驱动、V20路线或机械零点验收。

动态结果见`shadow_play/config/uart_pin_swap_trial_20261019.json`；不得将构建/SD暂存成功写成已对调、已收到回传或已运动。

实测已完成：用户新确认断电后加载对调位流，新确认上电无异常后两台各查询一次版本，均零回传、超时，3字节TX FIFO均由空到非空再排空。没有机械运动命令，也没有验证线端波形或握手；单纯交换方向未使通信恢复。

用户再次确认断电后，原标准位流已恢复。首次恢复的FPGA和关闭状态已成功，只在临时显示unit被回收后尝试`systemctl start`失败；已通过当前位流/启动门控，单独重建`shadow-uart-restored-hdmi`，未为显示再重载FPGA。`restore_standard_uart_image.py`已修正为显式重建临时服务；两项相关测试通过。最终仍OFF0、十路关闭、无故障/待提交、两路串口空闲，原锁和四启动文件摘要不变；执行器供电按现场最后确认保持关闭。恢复不代表机械回中，也不把无回传解释为电机损坏。

后续供电澄清：用户补充“刚刚没有叫我上电，现在我上电了”。以上供电描述保留为当轮报告，不能作为当前状态；此前对调轮的供电前提因此存在歧义，不能凭无回传排除方向问题，也不能反推此前一定没有供电。本次明确上电后，标准映射下各一次版本查询仍零回传。独立回环工具仅完成准备，用户表示暂时无法接回环、要求保持停止，实际回环未执行。详见`rail_power_recheck_20261019.json`和`uart_person_loopback_20261019.md`。
