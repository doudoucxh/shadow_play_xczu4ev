# 事故锁保留时的单路空载回中

`integrations/calibration/recovery_center_once.py` 是独立的恢复入口。仅在现场已解除所选云台与皮影的牵拉、确认剩余短杆和支架转动无干涉、有人能断电，并明确批准本次恢复之后使用。普通“继续”不视为批准。本程序不改变日常调角窗口的持续保持行为。

本次用户将 1/2 号云台的两节木杆从拼接处分开，云台上仍留短杆。这也可能解除皮影负载，但需要另行确认两段确实完全分开、短杆扫过区域无障碍；不能把拆开木杆等同于拆光支架或已检查全部行程。

程序只允许一次、一个通道、1500 μs（装配参考 135°）的提交，保持 3 秒后关闭。开始前要求寄存器仍与计划中的全关闭状态和序列号一致；其他九路脉宽不变且不使能。运行中检查状态、停止文件、期限及事故锁内容；失败不重试。Python 正常退出或中断时请求 OFF，进程失效另由已有 FPGA 心跳看门狗停止输出。关闭 PWM 不等于切断电源，也不保证轴保持位置。

这个入口显式提供一个经现场批准的单次回中例外；它不会删除、重命名或改写 `/run/shadow-pwm-motion-inhibit`、板端 `.motion-inhibit` 或主机事故记录。普通驱动对象及带杆采集程序继续受锁保护。恢复程序必须保留两份板端锁，锁缺失或内容改变就拒绝或停止。

计划包含 `approval`、`channel`、`expected_sequence`、`expected_pulses_us`、`linkage_disconnected`、`remaining_bracket_and_rod_clear`、`observer_ready`。批准字符串固定为 `single-unloaded-center-with-incident-locks-retained`；三项现场条件必须确认为真。不得提前填写真值。旧脉宽仅用于检测寄存器是否变化，不是物理位置反馈。

不带 `--execute-approved-unloaded-center` 时仅检查计划，不打开 MMIO。`--help` 也不访问寄存器。实际执行还需要该显式选项，不能将计划校验成功视为动作授权。

测试入口：

```text
python -m unittest discover -s shadow_play/tests -p test_recovery_center_once.py -v
```

11 项无硬件测试覆盖单通道固定脉宽、保持期限、最终 OFF、普通驱动仍被锁阻止、非预期角度/多路/重复提交拒绝、寄存器变化、现场条件缺失、锁缺失/变化、取消、授权超时、中断及失败不重试。它们不证明现场短杆或支架有足够间隙。

## 已脱杆两组的连续小步调试

2026-10-11 用户确认第一、第二组均已断开皮影长杆、余下短杆回中空间无阻挡，并在现场能随时断电。第二组上下连接曾脱开并重新安装，旧装配朝向和活动范围须重新核准。接电后 2、4 号出现清楚的机械响应；3 号只有很小的图像变化，没有实测轴角度。用户随后明确要求连续调试、发生异常由其立即通知，不再逐个动作询问。本授权限于当前有人值守的调试，不是无人值守或任意角度运行许可。

`recovery_jog_once.py` 为当前已脱杆的 1～4 号提供有限长度的小步动作，保留主机和板端事故锁，普通驱动仍被锁阻止。每段只使能一轴：先恢复经画面复核的起始指令，再每次最多变化 8 μs、间隔至少 120 ms；单段变化不超过 150 μs，起止脉宽限制在 1300～1700 μs，末端保持 1.2 秒后关闭输出。程序不支持老虎轴，也不支持直接带杆采集。这个较小窗口不等于新装配后的行程已标定。

计划必须具有 `start_pose_reviewed` 等现场条件。起始寄存器、序列号、输出状态必须匹配；不能只凭寄存器数值填写“起点已复核”。因手扳、重新装配、下垂等造成物理姿态变化时重新复核，不自动恢复。取消文件仍是 `/run/shadow-pwm-recovery-cancel`。中断、状态变化、锁变化、超时或提交结果不确定均停止，不自动重试或重新使能。

默认运行只打印脉宽序列，不打开寄存器；实际执行需 `--execute-attended-unloaded-jog`。10 项离线测试覆盖有限步进与间隔、范围和轴限制、旧状态、跳步、多轴、取消、外部停止、提交失败和默认无硬件行为。计划、执行日志和视频保存在忽略目录，正式恢复结果另外写入配置记录；相机画面不进入 Git。

## 接杆时的静态保持

`recovery_hold_pose.py` 只允许对已复核姿态的人物前四路或六路施加原有脉宽，不改变目标值。一次提交后保持最多五分钟，完成、取消、中断、状态改变均关闭输出；原动作锁保留。此功能用于让现场接杆时轴不易被推偏，不允许由此推断已完成带杆标定。若需要重新调整姿态，应先结束保持并独立核对新计划。取消文件由本次 `session_id` 唯一指定，启动日志会打印位置；全局恢复取消文件也有效。

## 第三组单点自由连接的恢复

用户随后确认人物右手的第三组无需拆开：人物其他两根杆已断开，此时第三组只单独悬挂人物，不会与其他杆相互牵拉，并明确要求直接试调。其物理条件不是“木杆已拆”，计划中必须保留 `linkage_disconnected:false`，使用单独授权 `single-free-connection-center-with-incident-locks-retained`，并确认 `free_single_connection:true`、`puppet_other_rods_disconnected:true` 和扫过空间。此例外只适用于 5、6 号，仍是单路 1500 μs、三秒后关闭，不能推广到多杆相连的人物或老虎。回中程序现有 12 项测试，包括此模式与完全脱杆模式的区分。

5 号回中后人物偏离了幕布工作平面，需要重新选择工作朝向。小步程序也允许上述明确的第三组单点自由连接模式，仍保留 `linkage_disconnected:false`，额外两项必须为真，范围、步长和速度不变；没有这些条件时 5、6 号继续被拒绝。先以 8 μs 的单步探测方向，再依据画面决定后续目标，不把旧脉宽当作实际起点。小步程序现有 11 项测试。
# 2026-10-11 正常停止方式修正

观察到相同脉宽再次启用时，部分轴仍改变姿态。HDL 的立即 OFF 会在任意相位拉低 PWM，因此可能截短最后一个高电平；这只是待硬件对比验证的原因之一，不能把寄存器回读当作轴位置。

恢复工具正常完成时改为：保持原脉宽、提交零使能掩码，在下一帧边界确认十路关闭，再解除 ARM。这个关闭提交会使序号额外增加一次。异常、取消、外部急停仍立即 OFF，不等待完整脉冲；未知结果不重试、不重新 ARM。普通动作锁保持有效。

验证：48 项 Python 检查通过；100 MHz Vivado 仿真中，在高电平期间排队关闭仍输出完整的 1520 μs 脉冲，此后不再出现下一脉冲。实际连杆标定和完整武打动作尚未完成。

接回人物前两根杆后的局部探测工具为 `person_local_probe.py`，默认只检查计划，不访问寄存器。必须记录已观察过的静态保持会话，确认接杆时没有扳动轴、两路画面和人员在场条件；不能从旧寄存器独立推断这些条件。

单次探测同时保持人物六路，只允许其中一轴改变 1～8 μs，静置一秒后返回原指令，再完整关断。老虎不启用，现有事故动作锁不解除，失败不回位、不自动重试。六项离线测试通过；工具准备完成不代表已经执行带杆探测。
