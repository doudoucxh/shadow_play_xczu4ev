## 改动与部署

- 浏览器以 30 Hz 为采样上限，Xvfb 原始 BGRA 经私有 tmpfs 传给 HDMI，省去每帧 JPEG 编解码。输入直接进入有认证的私有 X11，保留轨迹点与按下/释放事件。
- HDMI 复用线性缩放缓冲，内容相同的新包不再重复缩放/提交，仍检查时间戳；超时或无效包清空显示。采样率与提交率分开记录。
- 纸纹、暗边和角色调色/分片采用像素缓存，减少渐变和模糊阴影计算。保留按钮对比度，缓存背景禁止平铺。纸纹 PNG 可用 `hdmi_ui/tools/build_board_paper.py` 重建（Pillow），普通 UI 构建仍只依赖 Python 标准库。
- 仅无机构输出的 UI 相机路径允许首次采集等待 10 秒，后续等待和 250 ms 帧龄上限不变。预览生产限额改为 15 Hz，前端按请求开始时间安排下一次轮询，不叠加整段等待、不并发请求；实际速度以实测为准。

安装位置仍为 `/run/media/mmcblk0p2/piying/shadow-theatre-board-20261017-r4-runtime`。当前页面摘要及 64 项安装清单摘要见 `config/hdmi_ui_performance_20261018.json`。SD 的 `backups/perf-*` 和网页备份保留回滚资料，最终运行文件不含临时诊断代码。旧打包文件是历史版本，本轮以 Git 源码、校验清单和已更新板端目录为准。

## 验证与边界

Windows 显示/帧校验 17 项、板端 Linux USB 隔离回归 16 项、Node 页面生命周期 6 项通过；JS/Python 语法及 UI 68 项文件完整性检查通过。Linux 用例的发送器为测试替身，未访问真实机构。Windows 全 USB 测试最初有两项因缺少 Linux `fcntl` 导入失败，随后已在板端 Linux 完整运行 16 项通过。

最终返回主页，摄像头、音频停止；十路只读状态仍 armed=false、enabled_mask=0、sequence=0、faults=0、pending=false。1500 μs 只是寄存器指令，不代表机械回中。机构尚未安装、动作锁保留；没有增加开机自启，重启后仍按原部署记录准备显示环境。

原始串口日志与截图仅保存在本地忽略目录 `.review_work/ui_board_deploy/`，不进入 Git。早期仅测采样率、未确认页面状态的临时对照不作为最终性能依据。
