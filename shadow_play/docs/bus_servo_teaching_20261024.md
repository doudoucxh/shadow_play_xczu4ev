# 双总线舵机与手动示教上位机

2026-10-24。用户确认购买的是 **15kg 单轴版本，尚未换装，没有电平转换模块**。软件按随附手册中的 ZX15S、270°候选配置开发，实际标签、固件、量程及接线需换装时核对。本次仅做电脑与 FPGA 离线开发，没有连接 COM19、加载板端 FPGA、修改开机文件或发送实物舵机命令。

## 电脑上使用

双击项目根目录的 **`总线舵机示教上位机.cmd`**。默认“离线模拟”，点“连接”即可熟悉操作。此电脑使用现有 Python/Tk 和 pyserial，不需要联网安装。移到其他电脑时，安装带 Tk 的 Python 3.10+ 与 pyserial，然后在项目根目录运行：

```text
python -m shadow_play.bus_servo.gui
```

界面包含十路独立勾选、“人物六路”“老虎四路”“全选”、每轴目标角度与反馈角度、统一到达时间、轨迹曲线、录制/保存/载入、首帧准备、变速回放及停止。

- **单轴/多轴角度**：勾选要控制的轴，分别输入角度，设置到达时间，点“发送所选角度”。没有勾选的轴不会收到目标。超出限位或速度上限会拒绝发送；增大到达时间可以降低速度。
- **手动示教**：选择“手动拖动示教”，勾选录制轴，再点“开始录制”。程序请求所选轴卸力，并轮询实际位置；此时用手缓慢表演。扶稳机构后再卸力，卸力不是断电，也不保证能轻松反拖减速齿轮，不能强扳机械止点。
- **控制动作录制**：不卸力，开始时锁定录制轴；之后可重新勾选单轴或另一组轴，用角度设置按钮发动作，原录制轴保持不变。例如先勾选十路开始录制，再只勾选1号调整角度，就能同时记录整个机构的反馈；不以目标值代替实测值。
- **离线模拟练习**：开始手动示教后，改变目标角度并点“模拟手动拖动”，模拟反馈随之变化。模拟记录有明确来源标识，实机模式拒绝播放模拟文件。
- **停止**：界面停止按钮或 Esc 请求两路全部卸力，清除待处理目标。通信异常也结束会话，不重发、不自动恢复。停止广播不是逐轴停止确认，也不切断执行器电源。

录制默认 10Hz，可选 5/10/20Hz；这只是请求频率。两路分别轮询，六路一组的同帧角度不是同时采集。文件保存逐轴采集时间、实际平均频率及最大间隔，不承诺实机达到 20Hz。首次十路联调建议 5Hz，按实际反馈质量再调整；采样空档超过 0.5 秒或反馈失败时保留未完成记录。

## 第一部分：先演一遍，再复刻

换装与初次联调完成后，按以下流程录制新的第一部分。旧 PWM 剧本及旧中位值不自动迁移。

1. 连接“实物 / PS串口”，核对每路反馈、人物/虎轴对应关系与现场姿态。连接只查询，不自动回中。
2. 勾选参与这一部分的轴，选择“手动拖动示教”，扶稳人物/老虎，点“开始录制”。参与联动的轴应一起录入。
3. 用手缓慢完成第一部分动作；点“结束录制”正常保存。需要起始停顿时，在开始录制后保持一小段时间再动手。
4. 轨迹自动保存在 `shadow_play/logs/bus_servo/takes/`。可点“另存轨迹”命名，例如 `第一部分_正式示教.json`；不覆盖已有文件。
5. 选中整段记录或其中几路，先点“缓慢到首帧”，等实际反馈接近起点，再以 **0.5 倍**点“回放”。偏离首帧超过 1.5°会拒绝回放，不能靠反复点击跳过。
6. 核实杆件联动和皮影效果后，再根据速度限制决定是否使用 1 倍。回放结束会读所选轴末位置，偏差超过 2°报错；这项位置检查不代替表演效果验收。

“结束录制”与“停止”不同：前者生成完整轨迹，后者保留中断轨迹且禁止回放。正常回放结束后保持末位置；点停止或断开会请求卸力。没有自动循环、自动下一段或自动回原位。本版录制的是舵机时间轨迹，不录音，也没有把新轨迹自动拼入原声整场剧本。

## 接线与 ID

| 对象 | 逻辑轴 | 默认实物 ID | 新信号引脚 | 原接头 |
| --- | --- | --- | --- | --- |
| 武松 | 1–6 | 1、2、3、4、5、6 | **E14** | 原 9 号舵机信号 |
| 老虎 | 7–10 | 7、8、9、10 | **E15** | 原 10 号舵机信号 |

新 FPGA 将 E14/E15 改为双向单线半双工接口，115200/8N1。原 1–8 路不再输出 PWM；原 9、10 号的逻辑功能仍是老虎脚，只是它们不再各占一根信号线。丝杆原 F15/H13、H14/L13 四线保留，示教程序不操作丝杆。

每条总线的信号连接同组舵机，人物与老虎两根信号线分开；舵机电源使用满足型号要求的独立执行器电源，FPGA 与舵机公共地。**不要把舵机电源接进 FPGA 信号针。** 手册舵机供电标注 5–8.4V；这不是信号电平。供电电流、线径与接头容量按实际负载核算，人物六路的电源宜分支配电，不能将六路电流全部穿过一个未经核定的三针口。手册也因导线承载能力建议单控制器端口不超过五台。

**目前尚不能确认无转换模块直接接线可行。** FPGA 的 E14/E15 是 3.3V LVCMOS，资料没有明确保证舵机回传信号最高电压。先取得厂家电平规格或测量回传高电平及上电瞬态；只有双向电平兼容得到确认才能直连。否则需要与该单线半双工协议、115200 波特率兼容的接口，FPGA 侧保持 3.3V。普通 USB-TTL 的 TX/RX 不能简单并在信号线上，也不能将任意双线转换板直接套到这两根单线引脚。

出厂舵机可能全部是 ID 0，**先逐台改 ID，再并到总线上**。配置窗口只改软件映射，不给实物改 ID。独立 `provision.py` 支持板端逐台设 ID，默认只显示计划：

```text
python3 -m shadow_play.bus_servo.provision --manifest bus_servo.manifest.json --bus person --old 0 --new 1
```

实际执行须新 FPGA 已验证加载、电平已核实、该总线上只有目标一台舵机，并显式附加 `--execute --only-one-servo-connected --electrical-3v3-verified`。依次分配 ID 1–10；工具先读版本、单次写 ID、按新 ID 核验应答和版本，不扫地址或自动重发。若结果不明，停止检查当前 ID，不重复改写。

## 换装后的初次联调

当前 `config/bus_servo.json` 的三个就绪字段均为 false；**不能仅为启用按钮而改成 true**。它们分别代表已取得的实测事实：

| 字段 | 需要完成的工作 |
| --- | --- |
| `electrical_3v3_verified` | 验证信号电压、共地、半双工方向与供电；否则连只读查询也拒绝发送 |
| `hardware_verified` | 分别核实十台 ID、版本、工作模式、实际位置回传及正常卸力/控制响应 |
| `mechanical_limits_verified` | 按新的舵盘安装关系确定每轴安全行程、方向、速度及杆件组合余量 |

10–260°、30°/s 是当前软件候选限制，不是带杆实测安全范围。资料标称270°仅用于 `P500→0°、P2500→270°` 换算；首次核实必须检查型号和工作模式。软件支持180/270/360°，同一条记录绑定完整配置摘要，换 ID、量程、限位或标签后须重新确认记录，不静默转换旧数据。

首次板端加载必须在执行器断电、原输出关闭、停止相关 PL 使用程序的当次状态下进行。加载器要求当前 boot ID、原镜像摘要和实际 OFF 序号，原事故锁和四个开机文件保持。它只加载本次易失候选，不设置开机自启。历史 OFF210 不是今天的状态。

板端候选包预定目录为 `/run/media/mmcblk0p2/piying/bus-servo-v1`，PC 默认尝试当时枚举出的 PS 串口；COM19 只是历史候选，需确认真实端口。先手动登录板端 root，关闭占用串口的终端，再让上位机连接。程序不保存密码、不强占旧服务、不自动刷 FPGA。板端与电脑必须使用相同轴配置。

加载后禁止运行旧 PWM 回中/表演工具。旧 SP10 模块虽保留地址兼容，但物理输出已断开；新总线地址和镜像标记不同。独立安装包包含适配新镜像校验的 HDMI 运行副本，没有覆盖原服务或部署到 SD。

## 实现与数据

- `bus_servo/gui.py`：中文 Tk 界面；工作线程处理设备，不在界面线程等串口。
- `bus_servo/session.py`：示教、保存、按原时间间隔回放；调度落后会中断，不追赶式连发。
- `bus_servo/device.py`：双总线并行事务、实际位置和健康读取、FPGA 租约；传输成功不作到位确认。
- `bus_servo/service.py`、`transport.py`：PS 控制台 JSON 请求与序号检查，无重复请求执行、无命令重试。
- `hardware/bus_servo/`：两个带缓存单线 UART、AXI 寄存器、仿真、独立工程构建与镜像清单。

轨迹格式 `shadow.bus-teach.v1` 保存 `source`（模拟或真实反馈）、配置摘要、选择轴、每帧 `t`、原始 `positions`、逐轴 `axis_t`、完整性与结束原因。录制同时逐行刷新 `.jsonl` 日志，正常结束另写 `.json`。异常日志保留用于诊断，不自动修补成可播放记录。原始表演记录位于 Git 忽略目录；需长期备份时另存到明确的动作资料目录。

控制与反馈均使用 ASCII/PWM 的500–2500坐标。二进制协议仅用于读取健康寄存器0x48，避免把其0–4095坐标及方向误混入ASCII轨迹。无健康回传、模式不匹配、错误 ID、回声、校验失败或残留字节均中止。两条总线可并行，同一总线各轴依次发包，**不是严格同一时刻启动**；没有把控制器专用的 `{...}` / `$DST!` 当作裸舵机同步协议。

建立运动租约后，如果 1 秒没有有效主机操作续期，FPGA 在两路各发送一次 `#255PULK!` 并锁存故障，不自动重新使能。GUI停止也请求该广播。广播卸力能否实际生效取决于供电、线缆及舵机，不能作为硬件急停电路；机构异常仍由现场切断执行器电源。只读连接不建立运动租约，正常断开只读会话不会自动发卸力。

## 离线重建

Python测试：`python -m unittest shadow_play.tests.test_bus_servo`。本机受限环境须将 `tempfile.tempdir` 指向项目内可写的 `.review_work/bus_servo_test_tmp`。启动检查：`powershell -File shadow_play/tools/launch_bus_servo.ps1 -SmokeTest`。

Vivado2022.2依次以 batch 执行 `hardware/bus_servo/simulate.tcl`、`create_project.tcl`、`build_project.tcl`；生成目录是 `.review_work/bus_servo_20261024`。基于原双丝杆 UART 工程的 `base_dual_rail_design.tcl` 导出，保留 PS、DPU、相机、HDMI 和丝杆引脚；该导出与本次构建所用文件统一换行后相同，已保留为重建源码。`finish_project.tcl` 可续接已生成但尚未封装的工程。构建缓存不会进 Git。

使用 bootgen 将校验后的 `.bit` 转为 `.bit.bin`，再运行 `tools/package_bus_servo.py`，需指定 `--build`、新的 `--release` 和新的 `--bundle` 目录。打包器核对完整构建/RTL仿真、建立/保持/脉宽时序、物理引脚差异、HWH地址和文件哈希后生成独立安装包；已有目录不覆盖。`load_candidate.py` 不加 `--execute` 仅校验文件，不访问硬件。

资料依据为用户提供的 `2.简易二维云台(总线)/1.使用手册/简易二维云台使用手册【总线舵机】.pdf`（产品参数、角度换算、接线）与 `6.拓展资料/协议说明与产品使用说明书(Servo.C).pdf`（ASCII命令、健康寄存器、错误状态）。没有将厂家原始资料、截图或构建缓存加入 Git。
