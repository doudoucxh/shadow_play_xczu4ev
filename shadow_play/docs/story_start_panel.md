# 剧本起势控制面板

双击 shadow_play/tools/open_story_start.cmd。窗口启动不自动连接、不发送动作。

界面提供串口选择、当前十路指令、起势目标预览、已审核路线加载、路线启动和红色“停止 PWM”。当前指令不是实际轴角反馈，软件停止PWM不等于切断8V电源。没有无条件归位、强制ARM或解除事故锁按钮。

首次安装板端服务：登录板端root后关闭串口终端，在Windows运行 powershell -NoProfile -ExecutionPolicy Bypass -File shadow_play/tools/install_story_start_service.ps1 -PortName COM3。安装仅传输程序到 /tmp/piying-story-start-20261015 并检查语法，不启动服务或驱动电机；重启后需重新安装。

点击“连接”会识别已登录的root提示符并启动专用服务。只连接、读取和加载路线不会启用PWM。不得在同一个串口同时打开其他调节窗口。

“启动审核路线”仅在十路已经持续保持、当前指令和序号匹配审核起点、板子启动ID匹配、路线已复核时可用；点击时板端再次检查。停机、断电、手动转轴后不能沿用旧路线。不能为了点亮按钮伪填审核记录。

加载路线后，只有完全匹配审核记录的现存输出会进入最长15秒的静态交接保持，不改变脉宽或启用关闭的输出。期间仍需主机心跳；15秒内未启动会停输出。上传完成前若原有保持已经丢失，仍会拒绝启动，不能把此入口用于断电或手动移动后的接管。

剧本起势目标为 [1470,1212,1425,1514,1416,1740,1730,1250,1770,1740] μs，与所有轴1500 μs的装配中位不同。路线JSON必须沿用 attended_recovery_review.py 的审核字段，并提供 board_boot_id、expected_sequence，以及 route.target_id = "story_start_v3"。本次不附带可执行的示例路线，因为当前实际起点未核验。

恢复过程限定为预先审核的固定路线，非整场剧情。正常完成保持一秒后停输出；再次点击不会重新执行。串口心跳丢失超过0.75秒、调度异常、取消、状态变化或日志错误都会停止本次路线。急停请求无起点审核前提；若通信失败，界面必须显示尚未确认停机，现场仍需使用独立电源开关。

路线每帧还须满足既有各轴内缩10°的界限；这些仅是云台外界限，并不替代带杆联动审核。

Windows日志位于 shadow_play/logs/story_start/；板端动作记录为 /tmp/story-start-*.jsonl。日志中的指令完成不等于实际姿态通过。事故锁始终保留。

当前未知轴角、PWM关闭的机构仍不能使用此入口强制接管；这一限制在界面直接显示，不用警告框替代保护。
