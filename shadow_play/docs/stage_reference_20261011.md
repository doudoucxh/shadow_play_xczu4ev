## 工具与复现

新增 `stage_reference`，复用项目已有的 `CaptureGeometry`。它只读取 JSON 和保存的图片，输出几何 JSON、四角标注图和透视展开图，没有串口、PWM 或运动后端。输出目录必须不存在，交叉四角、参考区域外的采样点、图片尺寸不匹配及覆盖已有证据均会被拒绝。预览按物理宽高比生成，放大不提高原图分辨率。可选 `reference_points_mm` 支持已量出实际位置的内侧标记，不强制把标记中心当作整个幕面边界；物理参考点错误数量、交叉顺序或超出幕面会被拒绝。

```bash
cmake -S . -B build-static -DSHADOW_BUILD_CAPTURE=ON -DSHADOW_ENABLE_ALSA=OFF -DBUILD_TESTING=ON
cmake --build build-static --target stage_reference capture_geometry_tests -j2
cd build-static
ctest -R 'capture_geometry|stage_reference_offline' --output-on-failure
cd ..
./build-static/stage_reference config/stage_reference.front.20261011.json frame.jpg result-new
```

配置中的参考帧元数据用于追溯选点来源；调用者须核对自己提供的照片及拍摄条件。程序检查图片尺寸，不会自动发现相机位置改变。`frame.jpg` 应为记录对应的实际私有帧，不能拿随便一张照片沿用旧四角。

已在 Ubuntu 20.04、GCC 9.4、OpenCV 4.2 下编译通过。`capture_geometry` 和 `stage_reference_offline` 两个 CTest 项通过，后者包含 5 个用例，覆盖独立数值基准、内侧标记的实际坐标、异常参考点、尺寸变化与证据防覆盖。

## 后续标定的具体缺项

1. 四角标记已建立；仍需用幕面上独立实测的位置或长度检查投影误差，需要更高精度时再测标记的实际偏移。
2. 明确五根杆与皮影的实际连接点，尽量做可辨识标记；外观中心不能替代连接点。
3. 建立可验证的舵机起始姿态。用户已在断电后重新摆动老虎；此前脉宽寄存器和目测角度不能证明实际轴位置，且目前两端不便脱开。这个问题仍需现场机械处理或独立测量解决。
4. 之后才可复核各杆联动、逐组采集局部位置，并以重复点和未用于拟合的目标点验收。4 号的 PWM 波形已有示波器验证，但有效机械响应仍未确认。

本次 `actual_servo_state=null`、`motion_calibration_ready=false`。动作停止配置和板端锁保持原状；旧老虎运动样本仍被隔离，不能自动回放。本轮没有重新读取板端状态，停止状态引用的是此前 sequence 296 的证据，不将其写成本轮新测量。
