# 36 秒武打动作草稿与实机进度

2026-10-11 的目标是人物连贯武打、老虎前扑。当前交付为可运行的离线动作草稿；实机演出尚未完成。已有五个杆端的[静态坐标记录](point_coordinates_20261011.md)，尚无经实机验证的舵机角度到杆端坐标映射。

## 已完成的软件

- [fight36.draft.json](../assets/fight36.draft.json) 包含 24 个关键帧、36 秒动作；输入是五根杆的归一化目标，不是毫米或舵机角度。
- 剧本增加可选 `"interpolation": "quintic"`。每段使用 `10u³−15u⁴+6u⁵` 插值，关键帧处目标速度和加速度为零，段内不越过两端目标。后续仍经过映射器的限速和平滑。
- 原剧本不写该字段时仍使用线性插值。未知插值名称和非字符串值会被拒绝。
- 人物头部的竖直目标保持为 0，因为 4 号 G13 的信号虽已验证，机械响应仍未确认。
- `tiger_tail` 是原有协议名称，本次机构实际对应 9/10 号虎脚控制杆。前扑、扑咬是预期表演动作，目前没有独立下颌执行器，也没有滑轨动作。

| 时间 / 秒 | 编排意图 |
| --- | --- |
| 0–6 | 起势、举手戒备、试拳、收拳 |
| 6–13.5 | 虎伏身、第一次前扑，人物格挡和侧闪，虎后撤 |
| 13.5–21 | 人物左右手反击、回到戒备、双手连击 |
| 21–28.5 | 虎再次伏身前扑，人物格挡追击，虎退避 |
| 28.5–36 | 人物戒备、虎归位、人物收势 |

这些名称描述编排意图。五个点的归一化位移尚未映射为实物姿态，不能据此认定真实皮影能完成相应动作。首末全零表示剧本坐标原点，不表示向实机发送回中。

## Ubuntu 验证

使用独立目录 `/home/xianhaochen/piying/fight36-test-20261011-2025` 编译，没有覆盖已部署的板端程序，也没有访问真实电机接口。

4 项 CTest 测试通过：`mapping_behaviour`、`script_audio_behaviour`、`controller_behaviour`、`motor_protocol_behaviour`。新增检查覆盖插值端点、连接处缓起缓停、段内无超调和非法配置。

完整模拟按 20 ms 周期运行 38 秒（动作 36 秒，结束观察 2 秒），生成 10 轴共 19,010 条记录。使用 `tools/pc_check.py` 的 `csv_summary` 核验全部样本：数值有限、时间递增、角度与速度均在**模拟配置**范围内。最大单周期角度变化约 0.666385°，峰值速度约 33.31925°/s；结束时十轴均到达模拟中位。人物头部竖直模拟轴全程保持不变。

模拟配置中位为 90°，与本机装配参考 135° 不是同一配置；这些数字不是实机可用角度或安全范围。软件平滑也不能证明带杆机构没有碰撞、皮影拉扯或电流过大。

在该 Ubuntu 目录中可重复生成模拟结果，使用新的输出文件名：

```bash
cd /home/xianhaochen/piying/fight36-test-20261011-2025/shadow_play
../build/shadow_show --script assets/fight36.draft.json --seconds 38 --output ../build/fight36-repeat.csv
```

## 实机仍缺少的条件

老虎曾出现大幅动作并牵扯皮影，随后云台被手动掰回。当前 PWM 寄存器和旧日志都不能给出实际轴角度。用户确认杆件固定牢固，目前不能脱开，也不能无损松开扎带；本轮不再要求重复尝试拆卸。

恢复实机需要先取得可靠的已知起点，并检查皮影关节、连接及杆件联动余量。现有画面能定位杆端，但不足以恢复十路实际角度。单纯降低后续速度不能消除第一次接通 PWM 时追向未知目标的动作。

可靠起点建立后，还需要逐组采集小范围角度变化与杆端坐标的对应关系，验证组合姿态的可达范围，再把本草稿缩放、映射成实际轨迹；先分段低幅试演，再连接整场。此前异常的虎头、虎脚采样保留为诊断证据，不能自动回放。

本轮没有发送实机运动指令，没有解除本地或板端动作锁。依据项目 `AGENTS.md`，恢复前须“重新建立可靠起点并复核各杆联动”，动作锁“不得自动解除”。因此当前不能承诺在 22:30 前完成真实连续演出。
