# 动作轨迹预览

`trace_preview` 是独立的 C++17 命令行程序，不需要 Python、绘图库或开发板。它将控制器或原有 `mapper_demo` 输出的 CSV 转为一个可以在浏览器中打开的 SVG 文件。

`shadow_show` 默认输出 CSV；新增 `--motor-format jsonl` 用于整组电机目标交接，不能直接交给本工具。生成轨迹图时保留默认 CSV 或显式指定 `--motor-format csv`。

```bash
./build/trace_preview trace.csv trace.svg
```

Windows 构建后使用 `build\trace_preview.exe trace.csv trace.svg`。在文件管理器里打开 `trace.svg`，或拖入浏览器；放大后仍能看清细节。工具不覆盖已经存在的输出文件，再次生成时请指定新文件名。

## 怎么读图

- 每个电机轴单独一张图，保持 CSV 中首次出现的轴顺序；横轴是控制器运行时间，纵轴是角度。
- 蓝色实线是映射器输出的目标角度；橙色虚线是限位后、平滑和限速前的目标。二者差距可用于检查动作延迟和过快的关键帧跳变。
- 淡蓝色背景表示输入超时后正在回中；灰色背景表示无有效输入。
- 图顶三条事件带分别对应 `I` 输入截断、`A` 角度限位、`S` 速度限制。鼠标悬停可以查看对应的时间段。
- 每个轴独立选择角度范围；跨轴比较幅度时要看各自纵轴数值。
- 孤立采样点显示为圆点。相邻采样间隔超过该轴间隔中位数的三倍时断开折线，避免把没有记录的时段误画成连续运动。
- 如果 CSV 包含 `mode`，图底部列出模式变化时刻。`playback_s` 会检查格式，横轴仍使用 `time_s`，因此暂停期间也能看到输出行为。

**图里显示的是软件发出的电机目标，没有编码器或位置传感器的实测反馈。不能仅凭曲线判断实物电机已经到位。**

v0.3 的主杆名为 `wusong_neck`，连接武松脖子处；虎头 `tiger_head` 的杆固定在耳朵处。已有 `output/` 图可能包含历史 `wusong_body`/旧轴名，它们保留原生成结果，不自动转换成新的颈部映射。用本版程序、输入和配置重新生成可查看当前行为。

## CSV 格式

按表头名称查找字段，因此字段顺序可以不同。必填列为：

```text
time_s,axis_id,rod,angle_deg,limited_target_deg,input_state,input_clamped,angle_limited,speed_limited
```

新版控制器可以另带 `mode`、`playback_s`。其他附加列允许存在。布尔列支持 `0/1` 或 `false/true`。支持 UTF-8 BOM、CRLF、空行、双引号包围的字段及双写双引号转义，不支持字段中的换行。

不同轴的行可以交错，**同一轴的 `time_s` 必须严格递增**。每个轴允许样本数不同，轴缺失的时段不会被补成零。时间必须非负，所有已知数值字段必须是有限数值，轴名和杆名不能为空，同一轴不能中途换杆。

空文件、缺少必填列、字段数错误、NaN/Infinity、时间倒退及损坏的引号都会返回非零退出码，并给出行号或文件级错误。CSV 完整验证成功后才创建 SVG；输出路径不能等于输入路径，已有输出文件也不会被覆盖。

## 建议的检查流程

1. 先运行短测试剧本，确认每个动作的方向、幅度和限速是否符合预期。
2. 再运行完整 90 秒模拟，检查关键音效对应时刻的目标变化。
3. 回放触控或摄像头录制数据，检查突然跳动、输入缺失和回中过程。
4. 实物标定后使用真实配置再生成一份图；随后结合实物观察调整速度与动作范围。

此工具输出的是轴角度随时间变化的图。它尚未建立控制杆长度、皮影关节和幕布投影模型，因此不会显示完整皮影人物动画。
