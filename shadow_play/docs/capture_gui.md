# Ubuntu 单机标定采集界面 · v0.2

本页保留早期操作说明。**v0.4 交接请优先阅读 [机械队友使用说明](mechanical_handoff.md)**：本次使用观众视角 `front`，命令行可用 `--reference-view front`，新桌面入口默认前视角。旧演示配置仍保留 `rear` 以兼容旧数据。已新增板端服务框架与离线拟合，自动识别连接点尚未实现。

`shadow_capture` 是电脑端的 C++17 / Qt5 Widgets / OpenCV 采集工具。窗口在 Windows 电脑的 VirtualBox Ubuntu 中运行，USB UVC 摄像头直接接电脑并转交给虚拟机。Qt5 用于中文控件，OpenCV 用于取图和幕面透视展开。原有 `shadow_show` 和映射程序仍是独立工具。首次操作先看 [Windows / VirtualBox 逐步安装指南](capture_setup.md)。

你已确认有 Zynq UltraScale+ 板，但云台和滑台驱动尚未完成。本版 GUI 可以为五杆的配置轴和两个可控滑台生成目标，并通过 PC TCP 桥接发送到板端服务；实际运动仍需实现本项目自己的板端通信与驱动。摄像头不默认使用 Zynq 摄像头。具体器件、接口、单位、限位、寄存器和 PWM 参数需按实物确认。

## 1. 在 Ubuntu 编译

VirtualBox Ubuntu、WSL Ubuntu 和 Windows 是不同环境。依赖应安装在实际运行界面的 Ubuntu 里；从 Windows 复制过来的构建目录不可直接复用。

提供的源码包为 Windows 下的 `D:\ZYNQ\shadow-capture-v0.2.zip`。复制到 Ubuntu 主目录，在空目录解压，进入含 `CMakeLists.txt` 的 `shadow_play` 目录。以下命令假设解压后为 `~/shadow-capture-v0.2/shadow_play`；实际路径不同就使用你的路径。

```bash
sudo apt update
sudo apt install build-essential cmake pkg-config qtbase5-dev libopencv-dev fonts-noto-cjk unzip v4l-utils usbutils python3

mkdir -p ~/shadow-capture-v0.2
unzip -n ~/shadow-capture-v0.2.zip -d ~/shadow-capture-v0.2
cd ~/shadow-capture-v0.2/shadow_play

cmake -S . -B build-capture \
  -DSHADOW_BUILD_CAPTURE=ON \
  -DSHADOW_ENABLE_ALSA=OFF \
  -DBUILD_TESTING=OFF
cmake --build build-capture --target shadow_capture --parallel 2
```

编译成功后才会生成 `build-capture/shadow_capture`。若已有其他环境生成的 `build-capture`，换一个新的构建目录，并同步更改后面的命令。只复制几个 `.cpp` 文件不足以构建。

上面的 `mkdir -p` 只建立 ZIP 的解压容器；包内根目录为 `shadow_play`。后续 `--session` 指定的是另一个新的会话目录，不要提前 `mkdir` 建立它。

## 2. 先运行演示

在工程根目录执行：

```bash
./build-capture/shadow_capture \
  --demo \
  --config config/capture.demo.json \
  --session capture-sessions/demo-001
```

每次运行都使用一个**不存在的新会话目录**。程序拒绝覆盖或续写已有会话；第二次可把 `demo-001` 改为 `demo-002`。演示后端使用 `-1..1` 的无量纲模拟指令，这个范围不能用于实物电机，也不代表 PWM、角度或滑台毫米。

演示画面用于熟悉四点参考、选择杆、发送模拟指令、确认停稳、冻结、点击和保存。演示里的状态不是实物测量。

摄像头接入后，可以让演示后端使用真实相机画面：

```bash
./build-capture/shadow_capture \
  --backend simulation \
  --camera 0 \
  --config config/capture.demo.json \
  --session capture-sessions/camera-demo-001
```

`--camera 0` 选择电脑上编号为 0 的摄像头；编号不对时使用实际编号。VirtualBox 内还需让摄像头出现在该 Ubuntu 中，例如把 USB 摄像头连接到虚拟机，并确认没有被其他软件占用。终端有编译环境并不保证摄像头已转交给虚拟机。

离线图片可用于核对点击和坐标转换：

```bash
./build-capture/shadow_capture \
  --backend simulation \
  --image /home/你的用户名/test-frame.png \
  --config config/capture.demo.json \
  --session capture-sessions/image-demo-001
```

离线图片不能证明真实动作后位置已经稳定；它只记录该图片上的人工标注。

常用启动参数：

| 参数 | 作用 |
| --- | --- |
| `--backend simulation` | 默认后端，只在软件中采用指令 |
| `--backend manual_unconfirmed` | 手录真实控制工具中的指令，保存未确认样本 |
| `--backend external` | 通过文件交换请求真实驱动，需真实配置及 `--exchange` |
| `--demo` / `--camera N` / `--image 文件` | 分别选择合成演示、相机或离线图片来源；必须且只能选一种 |
| `--config 文件` | 本轮采集配置 |
| `--session 新目录` | 新建采集会话，拒绝覆盖已有目录 |
| `--exchange 目录` | 外部驱动文件交换目录 |
| `--ack-timeout-ms 毫秒` | 外部 ACK 超时时长，默认 5000，允许 250～60000 |
| `--stage-width-mm`、`--stage-height-mm` | 启动时覆盖有效幕布毫米尺寸，并重设四个参考角点 |

## 3. 接入同机真实驱动

实际连接关系为：

```text
Ubuntu GUI → JSON 文件交换目录 → PC TCP 桥接进程
                                     ↓ 网络
                           Zynq PS 接收服务 → 实际驱动 / PL → 电机

USB 摄像头 → Ubuntu GUI → 原始画面、点击坐标、采样元数据
```

先根据实际机构填写真实配置中的完整轴表、单位、初始值、安全上下限和每次最大变化量，为两个需要控制的滑台配置 `controllable: true` 及各自的范围和步长，再实现匹配 [外部驱动协议](../integrations/calibration/README.md) 的板端服务。`config/capture.demo.json` 标记为 `simulation_only: true`，不能作为外部实物配置直接使用；单位 `demo` 不能用于真实外部目标。

板端服务和驱动准备好后，在 Ubuntu 的工程根目录运行 GUI：

```bash
./build-capture/shadow_capture \
  --backend external \
  --config /home/你的用户名/capture.real.json \
  --exchange runtime/bridge \
  --camera 0 \
  --session capture-sessions/real-001
```

随后在另一个 Ubuntu 终端进入同一工程根目录，用 GUI 显示的会话 ID 启动 `integrations/calibration/tcp_bridge.py`，其参数和顺序见 [安装指南第 10 步](capture_setup.md)。文件交换接口本身不是实际硬件传输；PC 桥接提供 TCP 传输，板端仍需提供匹配的接收服务与运动驱动。

桥接启动后，首次发令前点击“读取 / 同步驱动状态”。同步只询问驱动最后采用的完整指令和滑台状态，不应使电机运动；同步成功后才允许发目标指令。超时或驱动故障后需重新同步，不能拿配置里的初始值猜测当前指令。外部模式要求实时摄像头，不能用合成画面或离线图片发实物目标。

收到驱动 ACK 只证明本次指令达到该驱动承诺的提交阶段。若驱动只是写入寄存器，应如实表示“寄存器写入/最后提交的指令”；不得显示成实际电机位置或已经到位。人工停稳确认是后续取样步骤，不能替代真实位置反馈。

GUI 的暂停用于停止安排下一条采样指令。实际停机、失联动作和独立看门狗由控制系统实现；机构急停使用实物急停方式。

### 驱动接口还没接好时手录

真实驱动或独立点动工具能执行实物动作后，也可以用 GUI 的摄像头画面手工登记其驱动值。驱动尚未完成时，可按 [安装指南第 7 步](capture_setup.md) 先用演示配置练习相机和手录流程。

先制作 `capture.real.json`，按真实机构填写完整轴表、实际单位、初始指令、限位、步长和滑台条件，设置 `simulation_only: false`，并填写实测有效幕面尺寸。演示配置的 `unit: "demo"` 和 `-1..1` 只能用于软件练习，不能抄成真实 PWM 或角度。

```bash
./build-capture/shadow_capture \
  --backend manual_unconfirmed \
  --config /home/你的用户名/capture.real.json \
  --camera 0 \
  --session capture-sessions/manual-001
```

该模式没有驱动 ACK，GUI 中的录入不会发送到电机。每次真实控制工具改变机构后，都要核对并录入完整轴指令及两个滑台条件，点击“登记以上命令（未确认）”，再确认停稳、冻结、点击和保存。样本明确标记为 `manual_unconfirmed`，不能当成驱动确认的数据；也不会因人工确认变成实测反馈。GUI 之外的运动不会被自动发现，需操作者重新执行取样步骤。

## 4. 建立幕布坐标

摄像头拍幕布背面，按背面观察的左右定义坐标：**有效幕布左下角为 `(0,0)`，向右是 `+x`，向上是 `+y`，单位 mm**。武松左右手标识仍按角色自身左右命名，不能因为摄像头视角交换标识。

输入的是实际参与采集的有效幕布宽度和高度，不是摄像头分辨率，也不是整个画框的尺寸。有效区域若小于整个幕布，就测量该区域。尺寸来自配置的 `stage.width_mm` 和 `stage.height_mm`；采集中不可修改。启动时可用 `--stage-width-mm`、`--stage-height-mm` 覆盖实际有效尺寸，此时四个毫米参考点重设为该矩形的四角。摄像头、幕布及四个参考标记在一轮采集中保持固定。

点击“设置幕面四个参考点”，默认参考点顺序为**左下 → 右下 → 右上 → 左上**，对应 `(0,0)`、`(宽,0)`、`(宽,高)`、`(0,高)`；若配置显式提供 `reference_points_mm`，按配置列出的对应位置点击。四点应覆盖同一平面的有效幕布区域，点击时核对位置；程序据此建立从图像像素到幕布毫米坐标的单应变换。不要把任意四点当成四个角，也不要沿同一条边取点。

四点设置成功后，在未冻结状态下点击已知的内部位置检查坐标误差。当前版本未校正镜头畸变，转换元数据标记 `lens_distortion_corrected: false`；四点完全吻合也不保证整个幕面误差为零。

“仅显示有效幕布（设置四点后自动透视校正）”默认勾选。设置四点时显示原始图，完成后自动切换为有效幕面展开视图，隐藏幕外背景；取消勾选可检查原图。幕面透视展开不等于镜头畸变校正。界面点选会转换回原始像素，保存的 PNG 始终保留完整原始帧。

摄像头移动、缩放/裁剪改变、画面镜像改变或幕布移动后，原变换已经不适用，应重新建立参考并开新会话。这个转换描述幕布平面上的位置；连接点偏离幕布平面时会产生投影误差，原始图片保留以供后续分析。

## 5. 逐点采集

五根杆可选择武松脖子处、武松左手、武松右手、老虎头部耳朵处、老虎尾巴处。五根杆不规定实际轴数；界面中的轴以当前配置为准。采集一根杆时，也要记录其他轴和两个滑台的状态，因为它们可能影响该杆的位置。

默认只显示当前杆的轴，勾选“显示全部电机轴（记录始终包含全部轴）”可核对或编辑其他轴。冻结、保存和逐组采样按钮保持在右侧下方；轴较多时，上方区域可以滚动。

配置为 `controllable: true` 的滑台可使用“− / ＋”点动或输入目标，与云台轴一起提交；其单位、限位和单次最大变化量来自真实配置。仅记录状态的滑台不下发运动目标。滑台移动后会改变杆的局部映射，需在该条件下重新采集。

手录模式记录已经由实际工具执行的值，输入仍要符合受控轴及滑台的上下限；单次运动步长限制由实际控制电机的工具落实。手录值的较大变化不会被本界面的发令步长限制拦截。修改任何命令或滑台字段后，应重新点击登记，再确认停稳。

每个采样点按这个顺序操作：

1. 选择本次采集的杆，核对完整轴状态和两个滑台状态。
2. 用轴旁“− / ＋”点动，或输入整组值后点击“提交以上整组目标”。有采样计划时，点击“执行当前采样组”。使用真实配置的单位，保持在已确认的限位和单次变化范围内。
3. 等待本次驱动 ACK，并观察机构。ACK 成功后，等机构实际停止，再勾选“我已观察机构停稳，并保持不动”。手录模式先由真实控制工具完成实物动作，再登记相应值和确认停稳。
4. 点击“冻结新画面 → 在幕布上点击连接点”。相机模式会丢弃确认后的 3 帧再取图，避免沿用运动前的旧冻结图。
5. 在冻结幕面上点击所选杆对应的连接点/关节点，核对右侧与本帧绑定的指令、原始像素和幕布 X/Y 毫米坐标，然后勾选“我已核对右侧指令及取点坐标”。
6. 点击“确认并记录本组数据和照片”，确认保存成功。
7. 默认情况下，保存后点击“执行当前采样组”执行列表中的下一组，再重复上述步骤。

取点错误时用“取消取点 / 重拍”重新确认停稳和冻结；本组不需要记录时用“跳过本组”。“暂停发令 / 恢复发令”用于暂停和继续后续请求。

“保存后自动执行下一组”默认关闭。操作者勾选后，在模拟或外部驱动模式中，列表样本保存成功会立即提交下一组受限指令；该选项只自动发下一组，不会自动确认停稳、点击或保存。手录模式禁用这个选项；暂停发令会取消勾选。

冻结期间不允许发送新运动目标。取消取点并发送新的轴或滑台指令后，原停稳确认、冻结和点击失效；修改手录字段也需重新登记。外部模式尚未 ACK、未确认停稳、未冻结、未点击、未核对右侧指令/坐标或状态失效时，不能保存有效样本。手录模式的样本保留未确认标记。

GUI 之外的控制工具调整滑台后，外部模式需再次同步。手录的可控滑台保留 `commanded` 来源和未确认后端；仅记录的固定滑台保留 `fixed_assumption` 与人工录入说明。滑台变化可能改变杆的位置映射，应在新条件下重新采集局部数据。

采样计划可由配置提供，`points` 可以省略或设为空数组，仅使用手动采集。当前计划条目列出完整云台轴目标，滑台保持最后采用值，可先手动点动滑台建立需要的采集条件。默认保存后需操作者显式执行下一组；人工点动和手动指令也遵循同样的确认流程。采样计划不是实物安全范围的来源，范围必须来自真实驱动和机构确认。

初次实物采集先固定两个滑台，分别获取各杆局部数据，再在已确认的滑台位置采集并记录。扩大命令范围和多杆组合前，确认机构可达性与相互影响。

## 6. 保存内容与状态含义

每个样本保留 `frames/sample_000001.png` 等原始 PNG 和 `samples.jsonl` 中的一条记录，JSONL 是分析时的权威元数据。`samples.csv` 用于快速查看和导入分析软件，完整语义以 JSONL 为准。

| 会话文件 | 内容 |
| --- | --- |
| `metadata.json` | 会话 ID、后端和来源配置等信息 |
| `config.snapshot.json` | 本会话实际采用的配置快照 |
| `requests.jsonl` | 已提交的同步/目标请求记录 |
| `capture_source.json` | 相机/演示/离线来源及时间语义、丢帧设置 |
| `calibration_000001.json` 等 | 单应矩阵、像素参考点、毫米参考点、有效幕面与图片尺寸、未校正畸变标记 |
| `frames/`、`samples.jsonl`、`samples.csv` | 原始图像与对应样本元数据 |

样本的 `calibration_id` 对应所用转换文件，便于追溯所用单位、限位与参考点。

样本至少包含当前杆、指令与 ACK 标识、冻结帧信息、点击像素与毫米坐标、**全部轴和两个滑台**的状态。不要只截取当前杆的两路指令后丢弃其余机构条件。

JSONL 的 `state.axes` 始终保存最后采用的指令，`state.feedback` 单独保存真实轴反馈或 `null`；不能把这两个数组合并成“实际角度”。`state.slides` 的每一项用 `state_kind` 说明滑台值的来源。`state.confirmed` 表示后端状态已经确认，手录模式为 `false`，不表示电机已到位或已经人工停稳。

手录模式中的 `state.accepted: true` 仅表示采集程序接纳了这份登记；是否有驱动确认，应同时检查 `state.backend` 和 `state.confirmed`。模拟模式的确认来自软件模拟，同样不能当作实物执行确认。

| 状态类型 `state_kind` | 含义 |
| --- | --- |
| `commanded` | 已提交的指令值，不能当成实测位置 |
| `measured` | 驱动明确提供的真实反馈值，需要保留其来源 |
| `fixed_assumption` | 操作者或配置给定的固定条件假设，需要记录 `assumption` 说明 |

不存在实际位置反馈时，实际反馈字段应为 `null`。手工输入初始值、点击停稳确认、收到 ACK 都不会自动产生位置反馈。后续拟合要结合状态类型决定哪些数据可以用于建模。

USB 摄像头的 `frame_read_at` 是电脑读到帧的 UTC 时间，`frozen_at` 是冻结时间，都不是硬件同步的曝光时间；未知读取时间为 `null`。丢弃 3 帧和人工停稳有助于减少旧帧问题，仍不能证明驱动命令与曝光时刻精确同步；原始图像及时间语义应在拟合时保留。

这批采集数据**不会自动替换**现有 `config/calibration.simulation.csv`，也不会直接变成映射器可用的 `calibration.csv`。需要先检查样本、剔除错误标注，拟合相应机构模型，验证误差及安全范围，再按最终映射器的参数格式转换；原有局部线性映射以归一化杆目标输出角度，不能直接读毫米坐标和任意驱动单位。

## 7. 常见问题

| 现象 | 检查 |
| --- | --- |
| 找不到 `cmake`、Qt5 或 OpenCV | 是否在当前运行 GUI 的 Ubuntu 中安装了第 1 节依赖 |
| CMake 找不到 `CMakeLists.txt` | 当前目录是否为工程根目录 |
| 可执行文件不存在 | 配置和编译是否已成功；构建目录名是否一致 |
| GUI 无法打开窗口 | 当前 Ubuntu 是否有可用桌面/显示会话 |
| 相机打不开或无新帧 | 相机编号、虚拟机设备连接、设备占用、当前相机画面是否正常 |
| 会话目录被拒绝 | 换一个尚不存在的新目录，不要覆盖原始采集结果 |
| 坐标方向或比例错误 | 有效幕布毫米尺寸、四角点击顺序、背面视角、镜像/裁剪是否一致 |
| 指令被拒绝 | 检查单位、完整轴集合、限位和单次最大变化量，不要扩大范围来绕过错误 |
| ACK 超时或报错 | 暂停采集，检查驱动进程和交换目录；确认硬件状态后再继续 |
| 保存按钮不可用 | 是否已完成登记/ACK、人工停稳、冻结、点选及右侧指令/坐标核对；之后是否修改过字段 |
