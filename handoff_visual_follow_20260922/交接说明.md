# 皮影戏工程：视觉模块交接（FOLLOW 基线）

日期：2026-09-22。接收对象：机械控制组。

## 1. 先看结论

用户已确认视觉任务基本完成，本包冻结当前 YOLOv8n Pose9 + DPU + FOLLOW 运行版本，供机械控制联调。不要替换为历史双 V2 模型、ARM-CHAIN 版本或旧 STABLE 入口。

**这是一份视觉运行交接包，不是已经接通电机的整机交付包，也不是完整 Vivado/PetaLinux 重建源码包。**

- 已实现：摄像头采集、180°旋转、DPU 推理、九关键点解码、单目标关联、运动优先防抖、HDMI 骨架显示。
- 当前模型入口：`follow/board_follow.py`，画面标识 `FOLLOW | ROT180`。
- 已有纯视频 SD 冷启动基线；最新 FOLLOW 在板上使用 `/tmp` 文件及临时服务。**重启后临时文件/服务消失，默认恢复纯视频，不会自动运行最新模型。**
- **尚未实现机械控制数据发送。** 目前关键点在 Python 进程内使用；每两秒的 `YOLO_STATUS` 是状态日志，不是逐帧关键点协议。
- 本次整理仅复制文件、记录接口和重跑本地测试，未访问开发板、未改变板上程序、未写 SD 卡、未驱动任何机械设备。

## 3. 环境与输入输出

- 开发板：正点原子 MPSoC-P4 / XCZU4EV，不是 Zynq-7020。
- 工具链基线：Vivado/Vitis 2022.2；板端 Linux，Python 3、NumPy、OpenCV、XIR、VART。
- DPU：B4096，指纹 `0x101000056010407`；已有硬件时钟基线 100 MHz。
- 模型路径：`/opt/shadow/yolo_pose9/model/yolo_pose9_b4096.xmodel`。
- 摄像头图像：1280×720；软件先旋转 180°，再将有效图像缩至 384×216，上下各补 84 像素，形成 384×384 RGB INT8 输入。
- 当前模型不使用旧 256×144 图像作为推理输入；旧 pose DMA 仍须正常排空，不能随意停掉。
- 画面显示和输出关键点均使用旋转后的正向图像坐标，不要再旋转一次。

既有流水线/防抖版测得更新吞吐约 28.6 FPS；最新 FOLLOW 短测空场约 28.6 FPS。DPU 单次约 15 ms，**不等于端到端只有 15 ms，也不代表整机达到 60 FPS**。当前包不含严格光学端到端时延或标准姿态精度验收报告。

## 4. 机械组接入位置与坐标约定

接入位置在 `follow/board_follow.py` 中：

```python
pose = stabilizer.update(boxes, scores, points, captured)
# 在这里复制有效结果交给非阻塞发送队列，不要在此等待串口或电机动作完成。
```

`pose` 为 `None` 或形状 `(9, 3)` 的数组，每行为 `[x, y, confidence]`。坐标单位为像素；原点是正向图像左上角，x 向右，y 向下。图像尺寸为 1280×720。不能将 384×384 网络坐标直接送给机械组。

| ID | 名称 | 含义 |
| --- | --- | --- |
| 0 | head | 头 |
| 1 | left_shoulder | 人体左肩 |
| 2 | right_shoulder | 人体右肩 |
| 3 | left_elbow | 人体左肘 |
| 4 | right_elbow | 人体右肘 |
| 5 | left_wrist | 人体左腕 |
| 6 | right_wrist | 人体右腕 |
| 7 | left_hip | 人体左髋 |
| 8 | right_hip | 人体右髋 |

左右按模型训练标签的人体语义，不是简单的屏幕左右。首次联调必须通过“只抬左手/只抬右手”确认，不要为镜像表演随意改动关键点 ID。

当前显示有效条件为置信度至少 0.25。异常跳点或低置信度点可能被置零置信度；**即使其 x/y 仍是数字，也不得当作有效点控制电机。** 该阈值只是当前视觉阈值，不是机械安全保证。

`sequence` 是本次运行的已发布采集序号；`captured` 是板端单调时钟，记录图像从设备内存复制完成的时刻，不是曝光时刻。`stabilizer.track_id` 是进程内跟踪编号，不是永久人物身份；丢失后重选可能换人。

当前只做二维上半身识别，没有真实深度、手指、腿部或三维关节角度。机械角度映射、比例标定、关节限位和皮影姿态约束由控制侧另行实现。

## 5. 建议约定的数据接口（尚未实现）

先确定控制器和通信方式，再实现协议。建议最少包含：协议版本、会话编号、帧序号、板端时间戳、track_id、是否检出、图像尺寸、旋转约定，以及九点的 x/y/置信度/有效标记。

- 无人、关键点无效时也要发送明确的无效状态；不能仅靠“没有新坐标”隐式表达。
- 使用容量受限的最新结果队列，发送不能阻塞视觉流水线；不要积压一长串旧动作。
- 接收端必须检查序号、超时、会话变化、点有效性和人物切换。两端时钟未经同步时，不要直接相减计算延迟。
- 丢失、超时、换人或通信故障时执行由机械组验证的安全策略；保持、限速回位或卸力取决于实际机构，不能统一假定某一种一定安全。
- 首次接通执行器应断开负载或低速限幅测试，设置独立急停；确认标定和左右映射后再联动。
- 不要把像素坐标直接作为舵机 PWM、位置或力矩命令。

## 6. 在现有同一块板上恢复 FOLLOW

以下流程用于当前已验证 SD/硬件环境，不是任意新板的一键安装指南。

1. 断电接好摄像头后上电，确认原始摄像头 HDMI 画面流畅；不要带电插拔摄像头。
2. 确认 `/dev/dpu`、上述 xmodel 和 `/opt/shadow/yolo_pose9/runtime` 存在。若基础环境缺失，先恢复完整既有系统，不要只复制一个 `.pt` 或 `.xmodel`。
3. 将 `follow/` 的六个 `.py` 文件逐个放到板上 `/tmp`，保持原文件名。可使用包内传输工具：电脑先让串口处于已登录 shell，关闭占用串口的其他窗口，在包根目录 PowerShell 执行下例（对六个文件分别执行）：

```powershell
.\host_tools\transfer.ps1 -Source .\follow\board_follow.py -Target /tmp/board_follow.py
```

工具固定使用 COM3、115200、8N1；其他电脑须核对串口号。每次确认输出 `TRANSFER_OK`，不要仅凭脚本退出认为成功。

4. 确认没有其他 YOLO/显示程序占用 HDMI。若当前 FOLLOW 正在运行，不要重复启动；若切换版本，应先正常停止旧服务，等待恢复纯视频。不要直接强制杀进程。
5. 在板端已登录终端执行（需要 sudo 授权，密码由项目成员单独交接）：

```sh
sudo systemd-run --unit=shadow-yolo-follow --property=Restart=no --property=TimeoutStopSec=10 /usr/bin/env PYTHONPATH=/opt/shadow/yolo_pose9/runtime:/tmp /usr/bin/python3 -u /tmp/board_follow.py
systemctl status shadow-yolo-follow --no-pager
sudo journalctl -u shadow-yolo-follow -n 20 --no-pager
```

若同名临时单元已存在，先检查其状态并处理，不要并发启动第二个显示进程。

6. 确认画面出现 `FOLLOW | ROT180`，人物和骨架正向。有人入镜后应出现 `POSITIVE_FRAME_INPUT_AND_DECODE_PARITY_OK`；日志正常不代替目视验收。

停止并恢复纯视频：

```sh
sudo systemctl stop shadow-yolo-follow
```

正常停止的恢复路径已在此前板载测试中验证。断电、强杀和硬件故障不保证软件清理执行。必要时冷启动恢复已验证 SD 基线。

**不要启用旧 `shadow-yolo-pose` 启动器，也不要在模型占用 HDMI 时运行 `shadow-video-init`。不要用 `base_runtime/runtime.py` 直接替代本包 FOLLOW 入口。**

## 7. 接手验收与剩余工作

- 冷启动先验证纯视频，再恢复 FOLLOW；当前未完成最新模型的永久安装/开机自启动。
- 自然下垂、叉腰、水平伸展、上举、交叉、快速抬落手，确认显示和跟随符合演示需求。
- 单独抬左手和右手验证点序、坐标方向及控制映射。
- 人物出画、手腕遮挡、背景有人和重新入画时验证无效状态和目标切换，不能持续执行旧目标动作。
- 输出接口、接收端看门狗、映射标定和机械限位尚未实现；先做不带执行器的数据回放，再做低速联调。
